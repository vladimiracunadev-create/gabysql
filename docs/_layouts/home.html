Qué sabe hacer hoy

Superficie SQL relacional clásica completa. Pensada para OLTP, scripts y embebidos — no para OLAP ni analytics distribuido.

DDL completo

CREATE TABLE con PK, NOT NULL, UNIQUE, DEFAULT, REFERENCES con ON DELETE RESTRICT/CASCADE. ALTER TABLE ADD COLUMN. CREATE [UNIQUE] INDEX. TRUNCATE.

DML completo

Multi-row INSERT, INSERT...SELECT, UPSERT (ON CONFLICT DO NOTHING/UPDATE), REPLACE INTO, RETURNING *. UPDATE/DELETE con WHERE completo, multi-fila, por subquery.

WHERE expresivo

Todos los operadores: =, <, >, <=, >=, <>, BETWEEN, LIKE con escape, IS NULL, IN, EXISTS. Combinaciones con AND/OR/NOT + paréntesis. 3VL ANSI.

JOINs ANSI

INNER, LEFT, RIGHT, FULL, CROSS, USING, NATURAL, multi-tabla, self-join. Index-loop optimization transparente para INNER/LEFT contra PK/índice del right.

Agregados + GROUP BY

COUNT(*), COUNT(DISTINCT col), SUM, AVG, MIN, MAX. GROUP BY multi-columna, HAVING con agregados directos o por alias, SELECT DISTINCT. Reporting básico cubierto.

Transacciones

BEGIN / COMMIT / ROLLBACK explícitos. WAL después-imagen con CRC32 por página y replay completo en cada arranque. Backup/restore/verify con checksum end-to-end via CLI.

Cuatro modos de uso, un solo motor

📟 CLI
Scripts, automatización, REPL interactivo.
gabysql exec mi.db "SELECT ...;"
🌐 HTTP server
App que conecta por red, multi-cliente.
gabysql-server -db mi.db -addr :8080
📦 Crate Rust
App Rust nativa, embebido, cero red.
use gabysql::{sql, storage};
🐳 Docker
Demo rápida con UI web (phpgabyadmin).
docker compose up -d

¿Dónde encaja?

Sí, para esto

  • Apps Rust embebidas que necesitan SQL real (no un KV).
  • OLTP clásico: lookups por PK + índices + JOINs equi-predicado.
  • Reporting básico con GROUP BY + agregados single-table.
  • Proyectos que valoran supply chain Rust pura.
  • Casos donde SQLite es restrictivo pero Postgres es overkill.

No (todavía)

  • OLAP analítico — DuckDB es la respuesta.
  • MVCC / multi-writer concurrente — Postgres.
  • Window functions, CTE recursivas, vistas materializadas.
  • Agregados sobre SELECT con JOIN (bloque futuro).
  • Compatibilidad wire-protocol con Postgres/MySQL.
